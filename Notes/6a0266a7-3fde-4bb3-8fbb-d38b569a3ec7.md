# PPTX 导入模板包：固定底图与可编辑槽位
Status: implemented
Since: 2026-09-26
Category: 决策

## Problem
本地 PPTX 提取原先只服务普通模板，快速模式缺少从原稿生成可复用组件的入口。直接转换完整 SVG 会触发现有复杂路径、图片与文字约束。

## Decision
实现和边界以 [模板包模块说明](src/landppt/services/template_package/README.md) 的“从本地 PPTX 创建模板包”为准。about 授权的底图加槽位导入现已使用当前用户的 template_generation 模型识别文本用途、版式和要点分组，几何与容量仍由代码校验。按用户后续要求，PDF 样式未匹配时读取 PPT 原有样式，缺失属性采用默认值并继续解析，仅显示提示；该路径 32 项定向测试通过。支持清除原主题文字，底图检查未确认残留，浏览器显示真实阶段与页码。已选纯文字版式按槽位生成内容，避免通用页面 schema 的字段冲突。2026-09-27 验证：135 项定向回归通过；真实模型、LibreOffice 及浏览器跑通小字号正文识别、替换、草稿保存与数据库回读。测试草稿已删除，截图和报告在 artifacts/pptx-ai-import。后续使用用户的 k8s 原稿和真实模型验证了全部 15 页 AI 识别；分组归一化、数字分组、长名后缀及重试提示已修复，超过要点上限的页面保留结果并要求调整。实际模板生成仍只有第 15 页通过，其余 14 页被容量校验拒绝，记录见上述 README 与 artifacts/pptx-import/k8s。没有改写用户已发布版本或项目页面。

## Alternatives considered
继续使用字号规则成本最低，但会把小正文烘焙进底图；保留通用内容 schema 最省改动，却会让混合字段版式反复不匹配。全矢量转换的编辑能力更强，但仍需复杂形状及布局契约支持。当前使用 AI 语义识别、代码校验与用户确认。

## Consequences
固定素材独立于用户图库，v1 哈希兼容；导入增加模型调用成本，需要渲染容器和可用的模板模型。AI 分析文本及坐标，不做扫描图 OCR；字体替换、复杂图形与分组需对照确认。旧包图片里的正文不可逆，必须用原 PPT 重新导入，重试生成不能清除。若真实样本继续出现正文固定或高失败率，应检查识别与容量数据，而非放宽发布校验。
